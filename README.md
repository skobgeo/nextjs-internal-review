# Lumen — стенд для интернал-ревью фронтенд-разработчика

Блог вымышленного продукта на **Next.js 16 (App Router)** с бэкендом на **Fastify + SQLite**.
Сайт работает, но в нём намеренно оставлены незаконченные места и дефекты — это и есть задания.

Формат: **одна сессия на 90 минут**, лайвкодинг с ревьюером и обсуждение вслух.
Пять заданий ядра идут в фиксированном порядке, у каждого свой лимит времени. В конце —
ревью чужого кода. Резерв берём, только если идём с опережением.

**Этот README можно и нужно прочитать до сессии.** Код заданий до сессии не открываем — это договорённость.

---

## Первые пять минут

1. Поднять окружение (см. ниже) и убедиться, что открываются http://localhost:3000/blog и http://localhost:3100/docs.
2. Открыть четыре вкладки: блог, форму `/contact`, страницу заявок `/admin/leads`, Swagger.
3. Запустить `pnpm test:core` в отдельном терминале и оставить в watch-режиме.
4. Посмотреть на карточки в блоге и назвать вслух, что с ними не так. С этого начинается T-01.

```bash
mise install               # node 24.21.0, pnpm 11.27.0
pnpm install
pnpm dev                   # оба приложения сразу: сайт на :3000, API на :3100
```

База SQLite создаётся и наполняется 24 статьями при первом запуске API. Начать с чистого листа: `pnpm db:reset`.
Подробности установки и что делать, если что-то не поднимается — в `docs/SETUP.md`.

## Как устроены данные

```
страница (Server Component)  →  lib/api/articles.ts  →  apiGet()  →  safeFetch()  →  zod-схема из lib/api/schemas.ts
                                                                                        ↑ тип результата выводится отсюда
клиентская лента             →  lib/api/articles-client.ts  →  та же схема, но fetch из браузера
форма                        →  app/contact/actions.ts (Server Action)  →  POST /api/leads  →  /admin/leads
```

Соглашения, которые пригодятся везде:

- API отдаёт **snake_case**, даты — строками ISO 8601 в UTC, списки — конвертом `{ items, total, page, per_page }`.
- Ответы API **валидируются zod-схемами** через `safeFetch`, который ничего не бросает и возвращает `Result<T, FetchFailure>`.
  Тип данных на выходе — `z.output` схемы: какая схема, такой и тип.
- Схема формы `leadInputSchema` из `@repo/contracts` **общая для фронта и бэка**. Сообщения ошибок в ней человекочитаемые.
- Кэш серверных запросов управляется через `revalidate` и `tags` в `apiGet`.

`pnpm tasks` печатает, где в коде лежит каждое задание. Маркеры вида `[T-03]` стоят в комментариях у нужных файлов.

**Не надо:** править `apps/api`, добавлять зависимости, переписывать ui-kit целиком, менять тесты.

**Состояние на старте:** `pnpm typecheck`, `pnpm lint` и `pnpm build` проходят.
`pnpm test` красный: падает **6 тестов** в `@repo/core` — это задания T-02 и T-06.

## Ядро

### T-01 · Типы от схем · 10 минут

**Симптом.** На `/blog` карточки показывают `undefined min read`, прочерк вместо даты, пустую обложку,
а пагинация — `Page 1 of NaN`. Ошибок в консоли нет.

**Где.** `apps/web/src/lib/api/schemas.ts`, дальше — всё, что подсветит компилятор.

**Готово, когда**
- [ ] в `schemas.ts` не осталось `z.any()`; схемы статей описаны по Swagger и через `.transform()` приводят ответ к доменной модели (camelCase, даты — `Date`);
- [ ] типы `ArticleListItem` и другие по-прежнему выводятся из схем, а не написаны интерфейсами рядом;
- [ ] `pnpm typecheck` зелёный;
- [ ] карточки показывают дату, минуты и обложку, пагинация — `Page 1 of 4`.

**Обсудим.** Список статей и список заявок приходят одинаковым конвертом — где здесь просится дженерик.

### T-02 · Debounce и таймеры в React · 15 минут

**Симптомы.** Три теста `debounce` красные. В поиске: наберите слово из шести букв и посчитайте
запросы в Network; наберите что-нибудь и сразу кликните по статье; после поиска посмотрите,
что на странице обновилось, а что нет.

**Где.** `packages/core/src/timing/debounce.ts`, `apps/web/src/components/blog/search-box.tsx`,
связка `app/blog/page.tsx` ↔ `components/blog/article-feed.tsx`.

**Готово, когда**
- [ ] тесты `debounce` зелёные, публичный API функции не менялся;
- [ ] слово из шести букв — один запрос к серверу;
- [ ] уход на статью во время набора не возвращает обратно на список;
- [ ] поиск меняет список карточек, а не только заголовок «Results for».

**Дефектов:** 3 в `debounce.ts`, 2 в `search-box.tsx`, 1 в связке поиска и ленты.

### T-03 · Бесконечная прокрутка · 15 минут

**Симптом.** Под списком написано «You have reached the end», хотя статей 24. Хук `useInfiniteList`
написан «на потом» — на `any`.

**Где.** `apps/web/src/components/blog/use-infinite-list.ts`, `article-feed.tsx`.

**Готово, когда**
- [ ] хук типизирован дженериком по элементу списка, без `any`, и ничего не знает про статьи;
- [ ] докрутка до конца списка подгружает следующую страницу автоматически (`IntersectionObserver`), кнопка «Show more» остаётся запасным вариантом;
- [ ] повторный вызов `loadMore` во время загрузки не запускает второй запрос;
- [ ] ошибка загрузки показывается и не ломает уже показанный список;
- [ ] пагинация внизу остаётся.

**Обсудим.** Что должно произойти с накопленным списком при смене запроса и что делать с ответом, который пришёл уже после этого. Почему пагинация остаётся.

### T-04 · Форма на Server Action · 20 минут

**Симптомы.** Форма отправляется, но проверьте четыре сценария: пустая форма; форма с одной ошибкой;
форма при выключенном API (`Ctrl+C` в терминале бэкенда); `/admin/leads` сразу после успешной отправки.

**Где.** `apps/web/src/app/contact/actions.ts`, `form-state.ts`, `apps/web/src/components/contact-form.tsx`.

**Готово, когда**
- [ ] данные валидируются той же `leadInputSchema` из `@repo/contracts`, что и бэкенд, до похода в API;
- [ ] ошибки показываются под своими полями — и локальные, и `422` от API;
- [ ] введённые значения не теряются при ошибке;
- [ ] сетевая ошибка и `429` дают понятное сообщение, а не error boundary;
- [ ] кнопка заблокирована на время отправки, результат объявлен живой областью;
- [ ] `/admin/leads` показывает новую заявку сразу после успеха;
- [ ] в `form-state.ts` и `actions.ts` не осталось `any`; состояние формы описано так, чтобы подошло и другой форме;
- [ ] форма по-прежнему работает без JavaScript.

**Обсудим.** `updateTag` против `revalidateTag`. Зачем валидировать и на фронте, и на бэкенде.

### T-05 · `next/image` · 8 минут

**Симптом.** Обложки вставлены обычным `<img>`: в карточку шириной 340 px и в телефон на 360 px уезжает
один и тот же файл 1280×720 в JPEG. Посмотрите в Network размер и формат картинок и что грузится сразу,
а что могло бы подождать.

**Где.** `apps/web/src/components/blog/article-card.tsx`, `apps/web/src/app/blog/[slug]/page.tsx`.

**Готово, когда**
- [ ] обложки через `next/image` с `sizes`, соответствующим сетке; в Network — уменьшенные варианты в современном формате;
- [ ] карточки ниже сгиба грузят обложки лениво, обложка статьи — как LCP-элемент (`preload`);
- [ ] место под картинку по-прежнему зарезервировано (нет сдвига макета);
- [ ] вы рассказали, что делает оптимизатор, зачем `sizes` и `fill`, чем `preload` отличается от `loading`.

## Резерв

### T-06 · Throttle · 6 минут

`packages/core/src/timing/throttle.ts` — заглушка на `any`: индикатор прогресса чтения дёргает её на каждый
`scroll` (см. консоль на странице статьи). **Готово, когда** тесты зелёные (leading + trailing, `cancel()`),
функция типизирована дженериком, консоль на статье замолкает.

### T-07 · Семантика и доступность · 10 минут

В `packages/ui/src/organisms/site-header/`, `templates/page-shell/`, `apps/web/src/components/blog/*` и
`contact-form.tsx` **семь дефектов** семантики и доступности. Пройдите сайт клавиатурой, выключите JavaScript
на странице блога, посмотрите дерево доступности. **Готово, когда** найдены и починены — с самых важных.

### T-08 · Дженерики для повторяющихся форм · 6 минут

`listSchema<TItem>()` для конверта `{ items, total, page, per_page }` в `schemas.ts`;
`toFieldErrorMap<TField>()` в `packages/contracts/src/errors.ts`, который знает имена полей формы.

## Как это проверяется

- **Тесты** — `pnpm test:core` в watch-режиме.
- **Компилятор** — `pnpm typecheck`: после T-01 он становится вашим главным помощником.
- **Браузер** — DevTools: Network, Console, Elements → Accessibility, режим устройства 360 px, «Просмотр кода страницы».
- **Страница `/admin/leads`** и `GET /api/leads` в Swagger — сохранилась ли заявка и что именно.

Критерии «Готово, когда» — общие для вас и ревьюера. Помимо них оценивается, как вы ищете причину,
что проверяете и как объясняете выбор.

## Правила

- Документация, Swagger, MDN, исходники в `node_modules` — можно и нужно.
  Документация Next.js 16 лежит локально: `apps/web/node_modules/next/dist/docs/`.
- Поисковик — можно. AI-ассистенты (Copilot, Cursor, ChatGPT, Claude) — нет.
- Не успеть — нормально. Гораздо важнее, как вы рассуждаете вслух: почему именно так,
  что бы вы сделали иначе, будь это прод.
- Если задание кажется странным или спорным — скажите об этом. Аргументированное несогласие
  с формулировкой засчитывается в плюс.

## Заметки о стеке

- **Next.js 16**: Turbopack по умолчанию, `params` и `searchParams` — промисы, `revalidateTag`
  принимает второй аргумент (а в Server Actions есть `updateTag`), у `next/image` проп `priority`
  заменён на `preload`, `next lint` удалён (ESLint запускается напрямую).
- **React 19**: `useActionState` возвращает три значения; формы с `action` сбрасываются после отправки.
