# Lumen — стенд для интернал-ревью фронтенд-разработчика

Монорепозиторий с маркетинговым сайтом на **Next.js 16 (App Router)** и бэкендом на **Fastify + SQLite**.
Сайт работает, но в нём намеренно оставлены незаконченные места и дефекты — это и есть задания.

Формат: **три сессии по 90 минут**, лайвкодинг с ревьюером и обсуждение вслух.
Задания не нужно делать заранее — репозиторий вы видите вместе с ревьюером.

---

## Быстрый старт

```bash
mise install     # node 24.21.0, npm 12.0.2, pnpm 11.27.0
pnpm install
pnpm dev         # поднимает оба приложения сразу
```

| Что | Где |
|---|---|
| Сайт | http://localhost:3000 (редиректит на `/en` или `/ru`) |
| API | http://localhost:3100 |
| **Swagger UI** | **http://localhost:3100/docs** ← контракт бэкенда, пригодится почти в каждом задании |

База SQLite создаётся и наполняется демо-контентом при первом запуске API.
Если нужно начать с чистого листа — `pnpm db:reset`.

### Команды

```bash
pnpm dev             # оба приложения (turbo)
pnpm test            # все тесты один раз
pnpm test:core       # vitest в watch-режиме для @repo/core     ← сессия 1
pnpm test:contracts  # vitest в watch-режиме для @repo/contracts ← сессия 1
pnpm typecheck       # tsc --noEmit по всему монорепозиторию
pnpm lint            # eslint
pnpm build           # прод-сборка
pnpm tasks           # список маркеров заданий с файлами и строками
pnpm tasks S2        # то же, но только по второй сессии
```

**Состояние на старте:** `pnpm typecheck`, `pnpm lint` и `pnpm build` проходят.
`pnpm test` — красный: падает **47 тестов**, и это ровно задания первой сессии.

## Карта репозитория

```
apps/
  web/        Next.js 16, App Router, порт 3000 — здесь большая часть заданий
  api/        Fastify 5 + Drizzle + SQLite + Swagger, порт 3100 — трогать не нужно
packages/
  core/       чистый TypeScript: алгоритмы, growth-логика, типы i18n (+ тесты)
  contracts/  zod-схемы и типобезопасный HTTP-клиент, общие для фронта и бэка
  ui/         собственный ui-kit по атомарному дизайну, CSS Modules
  eslint-config/, typescript-config/
```

Структура `packages/ui` — атомарный дизайн:

```
atoms/       Button, Input, Textarea, Select, Checkbox, Text, Icon, VisuallyHidden, Container, Stack
molecules/   FormField, ArticleCard, Breadcrumbs, Pagination
organisms/   SiteHeader, Hero, MetricsBand, FeatureGrid, ArticleGrid, CtaBand, SiteFooter
templates/   PageShell
tokens/      дизайн-токены (CSS custom properties) и reset
```

Правило ui-kit: компоненты не содержат сырых значений цвета и размера — только ссылки на токены
из `packages/ui/src/tokens/tokens.css`.

### Что уже сделано за вас

- бэкенд готов целиком, со Swagger и i18n по заголовкам `Content-Language` / `Vary`;
- дизайн-токены, большая часть ui-kit, разметка страниц;
- маршрутизация локалей (`proxy.ts`), загрузка словарей с бэкенда;
- тесты ко всем заданиям первой сессии.

### Как это проверяется

- **Сессия 1** — `pnpm test:core` / `pnpm test:contracts` в watch-режиме: зелёный тест = задание сдано.
  Типы проверяются глазами в редакторе (см. `packages/core/src/i18n/type-playground.ts`).
- **Сессии 2 и 3** — браузер: DevTools, режим устройства (320 / 768 / 1440 px), вкладка Network,
  «Просмотр кода страницы», Lighthouse. Плюс обсуждение вслух.

## Правила

- Документация, Swagger, MDN, исходники в `node_modules` — можно и нужно.
- Поисковик — можно.
- AI-ассистенты (Copilot, Cursor, ChatGPT, Claude) — нет.
- Не успеть всё — нормально. Гораздо важнее, как вы рассуждаете вслух: почему именно так,
  что бы вы сделали иначе, будь это прод.
- Если задание кажется странным или спорным — скажите об этом. Аргументированное несогласие
  с формулировкой засчитывается в плюс.

## Заметки о стеке

- **Next.js 16**: Turbopack по умолчанию, `params` и `searchParams` — промисы, `middleware.ts`
  переименован в `proxy.ts`, `revalidateTag` принимает второй аргумент, `next lint` удалён
  (ESLint запускается напрямую).
- **Бэкенд** отдаёт `snake_case`, даты — строками ISO 8601 в UTC, списки — конвертом
  `{ items, total, page, per_page }`. Локаль выбирается через `?locale=`, затем `Accept-Language`,
  затем дефолтная `en`; фактический язык ответа всегда в заголовке `Content-Language`.
- **Частичный перевод** — это не баг: две статьи из шести не переведены на русский,
  и бэкенд честно сообщает об этом в `content_locale`.
